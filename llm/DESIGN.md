# 파티 코치 구조 변경: 의도 기반 + DB 기반 (2026-10-20 결정)

## 왜 바꾸나

지금 구조는 로컬 4B 모델(Qwen3.5-4B + LoRA)이 혼자 여러 단계를 한다.

1. 도구를 고르고 인자를 적는다
2. 수백~수천 토큰의 도구 결과 JSON을 읽는다 (in-context)
3. 다음 도구를 고르고, 마지막에 답 문장을 쓴다

4B 모델에게는 이 과정이 너무 어렵다. 2026-10-19 데이터로 학습한 모델을 화면에서 써 보니 이런 문제가 계속 나왔다.

- 화면 파티의 "깜까미"를 다른 멤버(포푸니크·밀로틱)로 착각
- "울퉁불퉁멧 형태"에서 도구 이름을 포켓몬 자리에 넣거나 없는 포켓몬 이름(blinkous)을 지어냄
- 띄우지 않았는데 "화면에 띄움", 승률·비율 같은 숫자를 지어냄
- 같은 도구 반복 호출로 문맥 초과, 외국어(프랑스어·일본어 등)가 섞인 답

서버에 장치를 하나씩 덧대며 막았지만(아래 "지금까지 한 것"), 근본 원인은 모델이 맡은 일이 너무 많다는 것이다.

## 바꾸는 구조

| 누가 | 하는 일 | 언제 |
|---|---|---|
| AI 하네스 (오프라인) | 파티·샘플마다 설명을 미리 써서 DB에 저장 | 데이터를 적재할 때 한 번 |
| 로컬 4B 모델 | 질문을 **의도 + 조건(JSON)** 으로 바꾸기만 | 질문할 때마다 |
| 서버 (+ DB) | 의도로 DB 조회 → 샘플·파티 띄우기 → 미리 써 둔 설명과 DB 숫자로 답 | 질문할 때마다 |

```
질문: "빛의장막 리플렉터 없는 깜까미 샘플"
모델: {"intent": "sample", "pokemon": "깜까미", "without": ["빛의장막", "리플렉터"]}
서버: DB에서 조건에 맞는 샘플 → 화면에 띄움 → "깜까미 @ 빛의점토 (H32 B32 D2) …"
```

- 모델은 긴 도구 결과를 읽지 않는다. 입력이 짧아 빠르고, 숫자·이름을 지어낼 자리가 없다
- 이름·도구·기술 찾기는 먼저 코드(DB 이름 맞추기)로 하고, 모델은 의도 분류와 애매한 부분만
- 학습 데이터는 (질문 → 의도 JSON) 쌍이라 만들기 쉽고 학습도 짧다

## 의도 목록 (시작 메뉴판)

모델이 고를 수 있는 선택지. 목록에 없는 요청은 "모름·못 함"으로 답한다 (지어내지 않음).
써 보면서 부족한 것을 추가한다.

| 의도 | 질문 예 | 조건 | 서버가 하는 일 |
|---|---|---|---|
| sample | "한카리아스 샘플 짜줘", "울퉁불퉁멧 형태", "빛의장막 없는 건?" | 포켓몬(메가 폼 포함), 도구, 빼는 기술, 역할 | 조건에 맞는 샘플을 찾아 띄움 |
| party | "더블 파티 하나 짜줘", "한카리아스랑 어울리는 파티" | 핵심 포켓몬(선택) | 상위 파티를 바탕으로 띄움 |
| fill | "나머지 채워줘", "한 마리 더 추천" | 화면 파티 | 같이 쓰인 포켓몬 중 골라 띄움 |
| weakness | "이 파티 약점 알려줘", "상성 어때?" | 화면 파티 | 겹치는 약점과 받아 줄 멤버 |
| mega | "메가 누구한테 써?" | 화면 파티 | 메가스톤 든 멤버와 사용률 |
| item_usage | "깜까미 아이템 뭐 써?" | 포켓몬 | 그 포켓몬의 도구 사용률 |
| threats | "이거 약점 찌르는 포켓몬 누가 있어?" | 화면 파티 | 위협 포켓몬 목록 |
| unknown | "ㅁㄴㅇㄹ", "점심 뭐 먹지", "승률 몇 퍼야?" | - | "다시 말해 주세요" / "그건 못 해요" |

"얘", "그거"처럼 가리키는 말은 서버가 대화 기록으로 정한다 (지금 이야기 중인 포켓몬: 바로 앞에 띄운 1마리, 아니면 최근 질문에 나온 화면 멤버).

## 잃는 것

- 메뉴판에 없는 자유로운 전략 상담은 못 한다 ("아직 못 해요")
- 답 문장이 템플릿이라 딱딱하다 → 하네스가 미리 써 둔 설명으로 채운다

## 지금까지 한 것 (재사용)

에이전트 루프(도구 여러 번 호출) 위에서 서버가 일부를 맡게 해 둔 것. 새 구조의 부품으로 그대로 쓴다.

- `agent/answers.py`: 도구 결과로 답 문장 만들기 (샘플·파티·약점·위협·도구 사용률·샘플 없음)
- `agent/tools.py`: 샘플 검색 조건(메가 폼 이름, `item`, `without`), DB 한글 이름(`readable`, `party_names`),
  질문 속 도구·기술·포켓몬 찾기(`item_in`, `moves_without`, `pokemon_in`)
- `agent/loop.py`: 지금 이야기 중인 포켓몬(`subject_of`), 모델이 빠뜨린 조건 채우기, 안 띄우면 서버가 띄우기(`ensure_shown`)
- `agent/prompt.py`: 화면 파티 줄에 한글 이름과 ID (`— 깜까미 (sableye)`)
- `providers/qwen.py`: llama.cpp 서버로 생성 (GGUF Q8_0, 문맥 8192)

### 땜질 (새 구조가 되면 정리)

모델 글이 그대로 나가는 경우를 막으려고 넣은 것. 모델이 의도 JSON만 쓰게 되면 대부분 필요 없다.

- 답 글자 제한 문법 (한글·숫자·기호·정해진 영문만)
- 같은 구절 반복 잘라내기, 800자 넘는 답 자르기
- 도구 호출 뒤 덧붙인 글 버리기

## 단계

1. 의도 목록과 조건 확정 (위 표)
2. 서버에 "의도 → DB 조회 → 답" 처리기 (지금까지 만든 코드 재사용)
3. 의도 추출: 먼저 규칙(DB 이름 맞추기 + 키워드), 규칙으로 못 잡는 것만 모델
4. (질문 → 의도 JSON) 데이터를 `make_data.py`로 만들어 짧게 재학습
5. DB에 파티·샘플 설명 칸 + 하네스로 설명 생성
   - 설명을 쓴 모델·날짜·데이터 버전을 같이 저장, DB를 다시 적재해도 유지되게 따로 보관
   - 설명 속 숫자는 DB 값만 (학습 데이터 자동 검사처럼 근거 없는 숫자·이름 검사)
