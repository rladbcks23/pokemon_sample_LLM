# 파티·샘플 설명문 평가 기준 (하네스용, rubric v4 · 2026-10-23)

`DESIGN.md` 5단계: 하네스가 파티·샘플마다 설명을 미리 써서 DB에 저장한다.
설명이 한 번에 통과하기는 어려우니 **쓰기 → 검사 → 고쳐 쓰기**를 반복하고, 이 문서를 통과한 것만 저장한다.

```
근거 묶음 만들기 → 작성 → [1차] 자동 검사(코드) ─실패→ 고쳐 쓰기 (실패 항목만)
                              │ 통과
                              ▼
                        [2차] 심사(AI 감점) → 하네스가 100점 계산 ─미달→ 고쳐 쓰기 (감점 항목만)
                              │ 통과 (항목별 최소점수 + 합계 80점 이상)
                              ▼
                        저장 (status=passed)   ※ 고쳐 쓰기 횟수 제한 없음. 이유를 못 찾으면 "이유를 모르겠다"고 쓰고 넘어감
```

## 0. 근거 묶음 (작성·심사 모두 이것만 본다)

설명에 쓸 수 있는 사실은 하네스가 DB·back 도구로 미리 뽑아 준 **근거 묶음** 안의 것뿐이다. 작성 모델이 외운 지식으로 숫자·사용률·상성을 채우지 않는다.

| 대상 | 근거 묶음 내용 |
|---|---|
| 샘플 | 포맷, 포켓몬(메가면 메가 폼)·타입·종족값, 특성·도구·성격·SP(0 생략)·기술 4개, 기술·특성·도구 한글 설명(나무위키), `member_profile` 역할, 그 포켓몬 샘플의 형태 분포(shapes), 같은 포켓몬 다른 샘플과의 차이(도구·SP·기술), 출처(OP.GG/대회 이름·순위) |
| 파티 | 포맷, 6마리 각 샘플 요약 + 역할, `check_party`(역할·밸런스·중복·메가 수·경고), 겹치는 약점, `find_threats` 상위, 출처(OP.GG 상위/대회 이름·순위·선수) |

- 근거 묶음에 없는 것은 쓰지 않는다. 묶음에서 **계산한 값**(예: 메가 후 스피드 종족값 +30)은 `derived`로 같이 넘겨 숫자 검사에서 허용한다
- 심사 모델에게도 같은 묶음을 준다 (묶음 밖 지식으로 "틀렸다"고 하지 않게)

## 1차: 자동 검사 (코드, 점수 없이 통과/실패만. 하나라도 실패하면 바로 고쳐 쓰기)

학습 데이터 검사(`training/make_data.py`의 `numbers_grounded`·`names_grounded`·`FOREIGN`)를 그대로 재사용한다.

| # | 항목 | 실패 조건 |
|---|---|---|
| A1 | 숫자 근거 | 설명 속 숫자가 근거 묶음·`derived`에 없음 (승률·데미지%·확정타·"상위 5%" 같은 지어낸 수치 포함) |
| A2 | 포켓몬 이름 근거 | 묶음에 없는 포켓몬 이름 (위협·파트너도 묶음에 있는 것만) |
| A3 | 기술·특성·도구 근거 | 샘플에 없는 기술·특성·도구를 "가지고 있다"고 씀. 파티 설명이면 6마리 샘플 안에 있어야 함 |
| A4 | 역할 모순 | `member_profile` 역할과 반대되는 말 (CS 딜러를 "막이", HBD+깨불을 "딜러"라고 함) |
| A5 | 포맷 용어 | 더블 설명에 "기점잡이", 싱글 설명에 더블 전용 운용(속이기 견제·날따름 보호 등)을 주된 역할로 씀 |
| A6 | 출처 표기 | 출처·대회 이름·순위가 DB(`Team.source`·`event`·`placement`)와 다름. 리플레이를 근거로 씀 |
| A7 | 글자 | 외국 글자(`FOREIGN`), 마크다운(`**`, `#`, 표, 글머리표), 이모지, back 도구 이름(`check_party` 등) |
| A8 | 길이 | 샘플 80 ~ 350자, 파티 150 ~ 550자 (공백 포함). 문장 2 ~ 6개 / 3 ~ 8개 |
| A9 | 단정·과장 | "최강", "무조건", "필수", "완벽", "절대", "카운터 없음", "승률이 높다" |
| A10 | 중복 | 같은 포켓몬의 다른 샘플 설명(또는 다른 파티 설명)과 문장 유사도 0.8 이상 — 이름만 바꾼 템플릿 문장 금지 |
| A11 | 메가 | 메가 폼을 메가 전 이름으로 부름, 메가스톤 3개 이상 파티인데 선출 제한 언급 없음, 메가 2마리 이상 동시 선출을 권함 |

## 2차: 심사 (100점 만점, 감점 방식)

자동 검사로는 못 잡는 "게임적으로 맞는가, 쓸모 있는가"를 본다. **작성 모델과 따로 부른 심사 모델**이 근거 묶음 + 설명을 보고
아래 감점표에서 **해당하는 감점 규칙 ID와 그 문구를 고르기만** 한다. 점수는 하네스가 계산한다 (심사 모델이 점수를 직접 매기지 않아 매번 같은 기준으로 나옴).

- 항목 점수 = 만점 − 감점 합 (0점 아래로는 내려가지 않음)
- 같은 규칙에 여러 문구가 걸리면 "건당" 규칙만 여러 번 감점, 나머지는 한 번만

### 통과 기준

1. 1차 자동 검사 전부 통과
2. **모든 항목이 최소점수 이상** (하나라도 미달이면 합계와 상관없이 탈락)
3. **합계 80점 이상**

| 합계 | 판정 | 하네스 처리 |
|---|---|---|
| 90~100 | 우수 | 저장 |
| 80~89 | 통과 | 저장 |
| 70~79 | 거의 통과 | 감점 항목만 고쳐 쓰기 |
| 70 미만 | 다시 쓰기 | 근거 묶음부터 다시 보고 새로 쓰기 |

### 감점표

규칙 ID는 `항목-알파벳`. 샘플·파티 만점이 다른 항목(J2~J6)은 **파티 감점 = 표의 값 × 파티 만점 / 샘플 만점** (소수점 반올림).

**J1 게임 정확성** — 최소점수가 높아서 효과 오해 1건이면 바로 탈락

| ID | 감점 사유 | 감점 |
|---|---|---|
| J1-a | 기술·특성·도구 효과를 잘못 앎 (구애스카프가 방어를 올린다, 위협이 특수공격을 낮춘다) | 건당 10 |
| J1-b | 타입 상성을 틀림 (근거 묶음 약점과 다름) | 건당 10 |
| J1-c | 포맷 규칙 오해 (싱글에서 범위기 이득, 메가를 여러 번) | 건당 5 |
| J1-d | 틀리지는 않지만 효과를 과하게·애매하게 씀 ("거의 다 막아요") | 건당 2 |

**J2 역할 일치**

| ID | 감점 사유 | 감점 |
|---|---|---|
| J2-a | 역할이 틀림 (파티면 멤버 1마리당) | 15 (파티 멤버당 5) |
| J2-b | 역할 근거를 종족값만으로 씀 ("스피드가 빨라서 딜러") | 4 |
| J2-c | 세부 역할 빠짐 (내구조정·랭크업 딜러·물리/특수막이 구분) | 2 |

**J3 "왜"가 있음**

| ID | 감점 사유 | 감점 |
|---|---|---|
| J3-a | 구성 나열만 하고 이유가 하나도 없음 | 15 (전부) |
| J3-b | 드문 선택(사용률 10위 밖, 다른 샘플과 다른 기술·도구·SP, 파티면 의외의 멤버)의 이유가 빠진 것. 자속 공격기·사용률 높은 흔한 선택은 개별 이유를 요구하지 않음 ("자속 고위력기" 한 마디면 충분) | 각 4 |
| J3-c | 이유가 근거 묶음과 연결되지 않는 일반론 ("강해서 좋아요") | 건당 2 |
| J3-d | 근거 묶음에 이유가 있는데 "이유를 모르겠다"고 씀 (찾기 귀찮아서 모른다고 넘김) | 건당 4 |

### N/A (근거가 없어서 쓸 수 없는 항목)

- 근거 묶음이 부족해 쓸 수 없는 항목은 감점 대신 `"N/A"`와 사유를 낸다 (예: 그 포켓몬 샘플이 하나뿐이라 S1 불가, 위협 결과가 비어 P3 불가). 지어내게 만들지 않기 위해서다
- N/A 항목은 만점·최소점수 계산에서 빼고 **합계를 100점으로 환산**한다: `합계 = 얻은 점수 / N/A 뺀 만점 합 × 100` (통과는 그대로 80)
- J1·J2·J3는 N/A가 될 수 없다. N/A가 3개 이상이면 근거가 부족한 것이니 멈추고 가장 좋았던 설명 저장(`saved`)

### 심사 출력 형식 (JSON 한 개)

```json
{
  "deductions": [
    {"rule": "S1-a", "quote": "빠른 스피드로 상대를 압박하는 딜러예요", "fix": "생명의구슬형과 달리 구애스카프로 선공을 잡는다는 점 넣기"},
    {"rule": "J3-b", "quote": "기술은 지진, 역린, 스톤에지, 아이언헤드예요", "fix": "스톤에지가 어떤 상대를 위한 기술인지 근거 묶음의 기술 설명으로"},
    {"rule": "J6-e", "quote": "압박을 가하는", "fix": "압박하는"}
  ],
  "na": {"P3": "find_threats 결과 없음"}
}
```

- `quote`는 설명에서 그대로 옮긴 문구 (빠진 내용을 지적하는 규칙이면 `""`), `fix`는 고칠 방향 한 줄. 심사 모델은 설명을 직접 다시 쓰지 않는다
- 하네스가 `quote`가 설명에 실제로 있는지 확인한다 (없는 문구를 인용한 감점은 버리고 심사를 한 번 다시 부름)
- 하네스 계산 결과 예: `{"J1": 20, "J2": 15, "J3": 11, "S1": 0, "J4": 10, "J5": 10, "J6": 9, "S2": 8, "total": 83, "below_min": ["S1"], "pass": false}`
  → 합계는 83이지만 S1이 최소점수(6) 미달이라 탈락, S1만 고쳐 쓰기

## 고쳐 쓰기 규칙

- 작성 모델에게 **이전 설명 + 실패 항목(1차 항목 번호·걸린 숫자/이름, 2차 `deductions`)만** 준다. 지적 안 받은 문장은 그대로 둔다 (고칠 때마다 새 오류가 생기는 것을 막음)
- 최소점수 미달 항목을 먼저, 그다음 감점이 큰 순서로 알려 준다
- **횟수 제한은 두지 않는다.** 통과할 때까지 고친다. 대신 같은 자리에서 맴돌지 않게 아래 "이유를 못 찾을 때"로 빠져나간다
- 단, **같은 감점 묶음(규칙 ID들)이 3번 연속이면 멈추고 가장 좋았던 설명 저장(`saved`)** (나아지지 않는데 계속 부르면 구독 사용량만 씀)
- 반복 여부는 규칙 ID로 센다 (심사자가 같은 지적을 매번 다른 문장으로 씀)
- 고쳐 쓴 뒤 점수가 오히려 떨어지면 가장 좋았던 설명으로 되돌린다. 같은 설명으로는 2번까지. 되돌릴 때 실패한 시도에서 새로 생긴 감점을 "[남겨 두기]"로 알려 준다 (줄이다가 내용을 빼서 감점되는 순환 방지)

### 이유를 못 찾을 때: "모르겠다"고 쓴다

공개 샘플·대회 팀에는 근거 묶음으로 설명이 안 되는 선택이 있다 (흔하지 않은 기술, 이상한 SP, 굳이 이 도구). 이유를 지어내면 J1·J3에서 계속 걸리고, 지우면 J3-b로 걸려서 끝나지 않는다. 이럴 때는 **이유를 모르겠다고 쓰는 것이 정답**이다.

- 쓰는 방법: 무엇이 이상한지 + 근거에서 이유를 못 찾았다는 것을 "~요" 체로 짧게
  - "스톤에지를 넣은 이유는 공개된 자료로는 모르겠어요."
  - "공격에 SP가 없는데 왜 물리 기술을 3개 넣었는지는 알 수 없어요."
  - "흔한 생명의구슬 대신 왜 이 도구를 골랐는지 근거를 못 찾았어요."
- 언제 쓰나: 같은 규칙(J1-a·J1-d·J3-b·J3-c·S1-c 등)이 **같은 문장에서 2번 연속** 걸리면, 다음 고쳐 쓰기에서 하네스가 "근거 묶음으로 이유를 대거나, 못 대면 모르겠다고 쓰기"를 지시한다
- 지어낸 이유보다 낫다. 샘플을 고르는 사람에게 "이 부분은 출처에서도 설명이 안 된다"는 것 자체가 정보다
- 막는 것:
  - 근거 묶음에 이유가 있는데 모른다고 쓰면 J3-d (건당 4)
  - 설명의 선택(도구·SP·기술, 파티면 멤버) 중 절반 넘게 "모르겠다"면 근거 묶음이 부족한 것이니 멈추고 가장 좋았던 설명 저장(`saved`)
  - 말투는 정중하게 (불평·비꼬기는 J6-a)

## 저장할 것

설명과 같이: `rubric_version`(v4), 작성·심사 모델 이름, 날짜, DB 데이터 버전(근거 묶음 해시), 항목별 점수·합계·감점 규칙 ID, N/A 사유, 고쳐 쓴 횟수, "이유 모름"으로 쓴 선택 목록, `status`(passed: 80점 통과 / saved: 나아지지 않아 멈추고 가장 좋았던 설명 저장).
DB를 다시 적재해도 근거 묶음 해시가 같으면 설명을 유지하고, 달라졌으면 다시 검사한다.

## 기준 자체 점검

- 사람이 검수하지 않는다. 멈춘 경우도 가장 좋았던 설명을 그대로 저장해 쓴다 (점수와 멈춘 이유는 기록)
- 결과에서 틀린 유형을 발견하면 먼저 1차 자동 검사(코드)로 잡을 수 있는지 본다 (사용량 0, 매번 같게)
- 통과를 100점으로 두지 않는다. 문체·쓸모 같은 항목은 심사마다 1~3점씩 흔들려서, 100점만 받으면 고쳐 쓰기가 끝나지 않고 토큰만 쓴다.
  틀리면 안 되는 것(J1·J2, 1차 자동 검사)은 최소점수·통과/실패로 막고, 나머지는 합계 80점으로 본다
- "이유 모름" 목록을 모아 보면 근거 묶음에 빠진 정보(기술 설명, 같이 쓰인 포켓몬 등)가 보인다. 자주 나오면 묶음에 그 정보를 넣는다
- 배점·최소점수·통과 80점은 처음 정한 값이다. 첫 실행에서 대부분 한 항목 최소점수에 걸리면 그 항목 기준을 다시 본다

## 예시 (샘플)

통과 예 (근거 묶음에 구애스카프·S32·기술 4개, 다른 샘플은 생명의구슬형, 이 형태가 흔한 형태라고 가정):
> 구애스카프로 선공을 잡는 물리 딜러로, 공개 샘플에서 흔한 형태예요. 생명의구슬형과 달리 스피드에 SP를 몰아 빠른 상대보다 먼저 지진·역린을 꽂아요. 기술이 묶이니 막이가 나오면 바로 교체하는 게 좋아요.

- 감점: J5-b(첫 턴 행동 없음) −3 → J5 7점. 합계 97점, 우수

탈락 예:
> 한카리아스는 최강의 딜러로 승률이 높아요. 지진은 약 60% 데미지를 줘요. 기술은 지진, 역린, 스톤에지, 아이언헤드예요.

- 1차에서 A9 "최강"·"승률이 높아요", A1 "60%"(근거 없음)로 바로 고쳐 쓰기
- 1차를 고쳐 통과해도 2차에서 J3-a(나열만) −15 → J3 0점, S1-a −12, J4-a −10 → 최소점수 미달 3개
